Your store guide

Set up your business, publish location-linked inventory and manage your store.

1. Create your business account

  1. Open Create your business account.
  2. Enter your business name, email and a password of at least 12 characters. Confirm the password and acknowledge the terms and privacy policy.
  3. After account creation, sign in to the control centre.

Signup creates a separate business tenant and tenant administrator membership. It does not grant global super admin rights or join an existing store. Existing staff should use credentials and assignments issued by their administrator. There is no default production super admin password; the server operator provisions that account privately.

2. Create a store and confirm its location

  1. In the control centre, select stores under Resource, then New record.
  2. Select your tenant and enter the store name and full physical address.
  3. Enter a two-letter country code (for example NG), three-letter currency code (NGN), timezone (Africa/Lagos) and language code (en or yo).
  4. Set latitude and longitude. Use Use current location for store only when the device is at the actual store; otherwise enter the correct coordinates manually.
  5. Confirm status is active and tap Save record.

Leave a new record’s ID blank; the server creates it. Select an existing record before editing it. Device location fills coordinates only: confirm and enter the address yourself. An online listing is not proof that you own or operate a store.

Inventory automatically inherits the saved store address and coordinates. Changing the store address updates its inventory location association. Currency cannot be changed while inventory exists; ask the operator to arrange a controlled repricing migration.

3. Add products and stock

  1. Select inventory, then New record.
  2. Select the correct store. Enter a product barcode, a clear name, quantity and price minor.
  3. Use whole numbers for quantity and price. Tap Save record.
  4. Select the saved product to update its stock or price. Check the public storefront to confirm the result.

Prices are entered in the currency’s smallest supported unit. For NGN, ₦500.00 is 50000; for USD, $12.99 is 1299. Quantity 0 displays out of stock. A barcode must be unique within its store. Do not add a product under another store to reuse its stock.

Use descriptive names such as “Bottled drinking water 500 mL” to help product search. Online map findings do not import product inventory or verify prices. Supply and maintain your actual catalog yourself or through an authorized inventory integration.

4. Publish the store and configure checkout

  1. Select marketplace, choose your store, enter its category and description, enable the listing and save.
  2. Ask the super admin to enable the platform’s marketplace feature. Tenant and store feature settings cannot override a disabled parent feature.
  3. Ask the super admin to configure an enabled store gateway and the payments feature. Supported hosted providers are Stripe, Paystack and Flutterwave.
  4. Test with the appropriate provider test environment before the operator explicitly enables live payments.

Gateway setup requires a server-installed credential and a matching secret reference. Never paste a private provider key into the public-key field, a product description or a support message. The super admin manages gateway references in the GUI; the server operator installs the actual secret privately.

A published listing does not by itself enable live charging. Complete merchant onboarding and disclose applicable taxes, refund terms and contact details before live trading. Review the store participation agreement; this guide does not record acceptance on your behalf.

5. Give staff appropriate access

Ask the super admin to create staff accounts. Tenant administrators can assign existing users within their own tenant through memberships: choose a user, tenant, role and store where applicable, then save. The full staff directory is restricted, so ask the super admin to assist if a user is not selectable.

  • Super admin: platform-wide tenants, users, features, gateways, API keys and audit access.
  • Tenant admin: stores and staff memberships within the assigned tenant.
  • Store manager: assigned store, inventory and marketplace listing.
  • Cashier, exit verifier and auditor: scoped administration reads; dedicated cashier and exit-verification transaction screens are not available.

For a tenant_admin membership, leave the store empty. Other roles require a store in the selected tenant. To revoke an assignment, select the matching membership, check remove and save. Sessions for that user are revoked when memberships change.

6. Review orders and connect inventory tools

Under orders, use Reconcile payment to check the provider result. Confirm the order ID, store, currency, amount and verified status before releasing goods. Demo statuses represent simulations only. A browser redirect or screenshot is not proof of payment.

Pending or uncertain orders can hold stock. Reconcile them before accepting a duplicate payment or changing inventory to compensate. Refunds and abandoned-order handling require an operator process; do not assume that an interrupted checkout released its stock.

The super admin can issue store-scoped integration keys under api_keys. Supported scopes are inventory:read, inventory:write and orders:read. Copy a new secret once and keep it in your integration’s private configuration. Keys expire in 1–365 days and can be rotated or revoked. They cannot manage users or charge shoppers.

An inventory integration updates Global POS records through its API; it does not automatically connect an arbitrary merchant website. See the repository documentation for the API and server configuration.

Before your store opens

  • Confirm the store address, coordinates, country, timezone and currency.
  • Review product names, barcodes, quantities and prices on the public storefront.
  • Check listing visibility and feature/gateway settings with the super admin.
  • Test the shopper journey and provider verification before enabling live trading.
  • Give staff individual accounts and document payment, returns and reconciliation procedures.
My store does not appear

Check that both tenant and store are active. For marketplace visibility, check the listing and marketplace feature settings. A store may have public inventory without enabled checkout.

I receive an access-denied message

Confirm the account’s tenant/store membership. Global gateway, key and user administration require a super admin. Ask your administrator to correct the assignment and sign in again.

I cannot sign in

Check your email and password. Repeated failures cause a temporary lockout. Contact your provisioning administrator if credentials need resetting; there is no self-service reset page.

Use the isolated demo to practise with sample records. It cannot make live purchases. For day-to-day shopper instructions, share the user guide.
